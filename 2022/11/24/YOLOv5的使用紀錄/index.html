YOLOv5 實作紀錄：從資料標註到工業相機偵測

2022.11.24黃永成約 13 分鐘閱讀更新於 2026.09.30

在工業相機的實作中，我曾遇到 YOLOv7 無法即時更新畫面的情況，因此改用 YOLOv5 繼續測試。這篇把環境建置、資料標註、模型訓練與即時偵測串成一條流程，也留下除錯與延伸開發的紀錄。

本篇重點
  • 先建立獨立環境，再準備圖片、標籤與資料設定
  • 用訓練結果中的 best.pt 執行偵測
  • 依症狀查閱錯誤處理與相機、裁圖、通訊範例

原始實作記錄於 2022 年；以下操作畫面與程式範例保留當時版本。

以下是我在工業相機專案中使用 YOLOv5 的學習與除錯紀錄。

YOLOv7 在我當時的工業相機環境中，影像來源初始化時顯示：1/1: 0... success (640x480 at 0.00 FPS).。這個畫面不足以單獨判斷模型有問題，還需要檢查相機與影像讀取流程。
YOLOv5 與 YOLOv7 的部分操作指令類似。當時在自己的相機與程式環境中，YOLOv7 沒有順利更新影像，因此我改用 YOLOv5 繼續實作。這是特定環境的經驗，不能推論所有專案都有同樣限制。

YOLOv5-ultralytics-Github：https://github.com/ultralytics/yolov5 （Chinese 中文簡體說明）
閱讀以下範例時，請先對照當時的版本、目錄與相機來源，再調整成自己的設定。

操作說明

  • 使用 Anaconda 管理 Python 環境，讓相依套件與其他專案分開。
  • 至Anaconda官網選擇符合系統與專案需求的版本：https://www.anaconda.com/products/distribution
  • 安裝完成後，使用 Anaconda Prompt (anaconda3) 來建立 YOLOv5 開發環境。

訓練與驗證資料

準備資料時，先分開訓練集與驗證集：訓練集用來學習，驗證集用來觀察模型在未參與訓練的資料上的表現。

選擇型號

這份實作以 YOLOv5s 預訓練權重開始訓練。不同型號在速度、大小與表現之間有取捨，請配合自己的硬體與需求選擇。
模型型號的比較可查閱專案 README；不要把單一型號視為所有場景的最佳選擇。

開始訓練

epochs：
可先以 300 個 epoch 作為這份練習的起點，再觀察訓練與驗證結果；不是所有任務都應使用固定回合數。
需要延長訓練時，依驗證表現調整回合數，避免只因尚未達到某個數字就持續增加。
batch size：
batch size 受記憶體、模型與圖片尺寸限制，也可能影響訓練表現。先使用可穩定執行的設定，再依結果調整。
超參數：
超參數檔名與位置依專案版本而異，請查看 data/hyps 等目錄及 --hyp 的設定；原文 hpy.scratch.yaml 的拼字不宜直接照抄。先保留所用版本的預設設定，建立可比較的基準。
資料增強可增加訓練時的變化，但是否有幫助需由驗證結果判斷；過強的變化也可能不符合實際場景。
調整 loss 各項權重時，需理解其用途並控制其他條件，不應把降低某一項權重當成通用的過度擬合解法。

  • 若訓練完之後，將最新的.\runs\train的目錄下，
    yolov5s-train最新資料夾之.\weights\best.pt的檔案可依原範例複製到主目錄.\yolov5-master之下，或直接在偵測指令指定權重路徑。

    執行 detect 時，--weights 必須指向訓練產生的權重；原範例把檔案複製到主目錄只是方便使用相對路徑，也能直接指定原位置的 best.pt 檔案。

常見錯誤與處理方式

  1. OMP: Error #15: Initializing libomp.dylib, but found libiomp5.dylib already initialize
    • 辦法１：
      原紀錄曾在 train.py 中使用下方 KMP_DUPLICATE_LIB_OK 繞行方式。它可能掩蓋 OpenMP 重複載入的衝突，應先檢查套件來源與相依版本，不把此設定視為已修復：
      • 示意圖：
    • 辦法２：
      舊筆記曾記錄刪除 \Anaconda3\pkgs 中含有 libomp.dylib 的快取。這不宜當作一般修復步驟；應先確認重複載入的執行期與套件來源，再在獨立環境中處理相依衝突。
      • PKGS的概念：
        在 Anaconda 環境中，可用 conda install，而python中是pip install，
        也可以使用 pip，但兩種工具混用時需核對套件來源與相依版本；不是所有套件都只能透過 conda install。
        在conda的設計中，目錄’pkgs’是下載、存放緩存，以及提取下載的conda包的地方。同時，anaconda一起攜帶的包也會放在這裡。
        建立 envs（環境）時，套件檔案可能以連結等方式重用 pkgs目錄，以減少重複檔案；實際方式依平台與設定而異。
  1. UnicodeDecodeError: 'cp950' codec can't decode byte 0x93 in position 25: illegal multibyte sequence
    這類錯誤表示讀取編碼與檔案內容不相符。先檢查 .yaml 的儲存編碼與程式讀取方式，不要直接把原因歸結為中文內容或作業系統。
  • 此專案使用 UTF-8 設定檔時，檔案的儲存與程式讀取編碼需一致。
  • 可到控制台>時鐘和區域>地區>系統管理>變更系統地區設定> Bata:使用Unicode UTF-8提供全球語言支援
    的選項打勾前，先確認是否需要改變系統層級的編碼；本篇錯誤應優先檢查檔案及讀取端，不必先調整整個系統。
  1. export GIT_PYTHON_REFRESH=quiet
    若 GitPython 找不到 Git，先確認 git 執行檔已安裝且可由 PATH 找到。quiet 只影響訊息處理，不會安裝 Git；下方保留當時的安裝指令。

提升YOLO辨識度

以下整理改善資料集的方向，作為檢查清單。圖片數量與背景比例是參考建議，仍需依任務和驗證結果調整。

  • 參考連結：https://blog.csdn.net/flyfish1986/article/details/120704968

數據集方面

  1. 每個類別的圖像
    官方訓練建議提到每類約 1,500 張以上圖片，這是改善資料涵蓋度的方向，不是程式開始訓練的硬性限制。

  2. 每個類別的實例
    實例指的是標註的目標物件，不等於圖片張數；同一張圖片可包含多個實例。官方建議每類累積約 10,000 個實例，仍需配合場景與標註品質評估。

  3. 圖像的多樣性
    資料集應涵蓋預期使用的場景，例如光線、角度、距離與相機差異。依任務選擇變化，不必為了湊數加入無關圖片。

  4. 標註的一致性
    對任務指定的類別一致標註，避免同一類目標有時標、有時漏標，讓模型學到矛盾的訊號。

  5. 標註的精度
    依一致的規則讓框貼合目標，並抽查漏標、錯類與過大的框。標註品質需與資料量一起評估。
    背景圖像：背景圖像是圖像裡沒有感興趣目標的圖像，加到數據集以減少誤報（FP）。
    建議約0-10%的背景圖像，以幫助減少FP（COCO數據集有1000張背景圖像供參考，佔總數的1%）。

完成訓練後，先檢查什麼？

確認權重檔案確實存在，偵測指令讀取的是預期的檔案，並對照驗證圖片上的框、類別與漏判情況。訓練結束只表示流程完成，還需要用與訓練資料分開的圖片判斷是否符合使用需求。

資料切分與數量建議可查閱 Ultralytics 訓練資料說明；完整操作流程見自訂資料訓練教學。
