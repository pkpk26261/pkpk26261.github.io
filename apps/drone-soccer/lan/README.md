# FLIGHT CLUB 多人正式賽

一台主機提供統一賽事大廳、服務管理中心與多個獨立賽場。每個房間使用自己的權威比賽環境，平板透過 HTTPS／WSS 傳送搖桿輸入並接收該場 3D 狀態。各房的玩家、比分、時間、鏡頭、暫停與故障復原互相隔離。獨立觀眾頁面適合電視與投影。沿用現有紅藍編成、前鋒／防守、飛控、碰撞、AI、倒數、三局兩勝、局間休息、點球與驟死規則。

## 掃碼直接加入（新版預設）

新版 Windows 應用程式使用公開可信的 HTTPS 遊戲入口。主機與玩家都需網際網路連線；玩家掃 QR 後直接開啟 `/play?code=六位房碼`，不安裝憑證、不啟用裝置信任，也不經過舊版憑證導入頁。「複製網址」同樣保留本場房碼。操作說明見 [多人連線指南](setup.html) 與 [啟動器說明](../desktop/README.md)。

1. 在應用程式啟動掃碼連線，等待公開入口顯示就緒。
2. 由主持人建立房間、選擇賽場與編成，再顯示 QR。
3. 玩家掃碼、輸入暱稱並選席位，連接搖桿後準備；觀眾可直接觀看。
4. 活動結束時由啟動器保存並停止服務。重開連線後網址可能變更，應分享目前的 QR。

公開連線尚未就緒或已中斷時，前端不以私有 IP 或憑證設定頁代替邀請。QR 圖片與分享網址會清空，待入口恢復後再顯示。`/api/config` 以 `accessMode: "online"`、`publicReady`、`directJoin`、`joinURL` 與 `invitationURL` 表達狀態；未就緒的公開網址欄位為 `null`。準備好的加入網址只使用公開 HTTPS `/play`，所有控制封包仍經 WSS 與原有伺服器安全檢查。

掃碼連線採獨立的 `.webduino-lan/direct-qr/` 資料範圍，舊版區網的房間與憑證不會因此公開或變動。低階 `server.cjs --online` 只建立私有來源；公開入口由應用程式連線程序建立並驗證後設定，單獨執行這個參數不會自行產生可分享 QR。它不開 HTTP 憑證下載埠，也不要求玩家安裝 CA。

下列安裝、私有 IP 與裝置信任說明屬於舊版區網模式，保留供既有現場使用，並非新版掃碼連線的操作流程。

**目前已通過桌面瀏覽器與六席 WSS 模擬測試；尚未完成兩台實體平板＋兩支藍牙搖桿的驗收。** 不可將模擬測試視為硬體相容保證。詳細紀錄見 [驗證紀錄](../docs/本機正式賽驗證.md)。

依使用者 2026-11-02 指示，本次先交付軟體及操作文件，實體設備驗收待設備備妥後進行。

## 舊版區網模式：安裝與啟動

舊版 Windows [FlightClub.exe](../../../output/flight-club/FlightClub.exe) 與手動區網伺服器沿用遊戲目錄內的 Node、Python、Chromium 及套件。這個模式需要現場裝置信任；若要玩家免憑證掃碼加入，請使用上方的新版掃碼連線流程。

需要 Node.js 22 以上、Python 3.9 以上及支援 WebGL 的主機。首次安裝需要網路；套件、Chromium 及憑證完成安裝後，比賽不需要網際網路。

在專案根目錄開啟 PowerShell：

```powershell
cd apps/drone-soccer/lan
npm install
npx playwright install chromium
python -m pip install -r requirements.txt
node server.cjs --list-addresses
```

本目錄也提供 `pnpm-lock.yaml`。使用 pnpm 時執行 `pnpm install --frozen-lockfile --node-linker=hoisted`；`hoisted` 適用不支援符號連結的 exFAT 磁碟。

從網卡清單選擇平板可存取的 IPv4 位址。以下 `192.168.10.2` 只是這次測試主機的網卡位址；請換成自己現場的位址：

```powershell
python setup-certs.py --address 192.168.10.2
node server.cjs --address 192.168.10.2 --port 8443 --setup-port 8081
```

如果已安裝 Google Chrome，可省略 Chromium 下載並使用：

```powershell
node server.cjs --address 192.168.10.2 --channel chrome --setup-port 8081
```

保持終端機開啟。它會列出：

- **服務大廳**：`https://LAN-IP:8443/`，供玩家與觀眾查看賽場／房間，點選加入或輸入代碼。
- **服務管理網址**：`/admin#admin=管理金鑰`，僅主持人保管。首次啟動產生金鑰並保存在主機；開啟網址後金鑰從網址列移除，改用有效 12 小時的 HttpOnly／Secure／SameSite=Strict cookie 登入，不將金鑰存入網頁儲存空間。
- **玩家 HTTPS 網址**：例如 `https://192.168.10.2:8443/play`，供已完成主機憑證信任的裝置使用。
- **公開裝置導入網址**：例如 `http://192.168.10.2:8081/`，供首次掃碼的裝置下載公開根憑證及確認連線；不提供遊戲、登入或管理功能。

按 `Ctrl+C` 安全停止。金鑰、賽場、房間、席位重連資訊與比賽檢查點保存在使用者家目錄 `.webduino-lan/service/state.json`，另保留上次寫入的 `.bak`。檢查點約每 2 秒寫入磁碟；正常停止會再保存一次。重啟後進行中的房間以暫停恢復，玩家須用原分頁重連並重新準備；原本未開賽的房間仍可正常開賽。管理者須重新登入。突然斷電可能失去最後約 2 秒或尚未成功寫入的變更；此備份不是資料庫級的斷電保證。檔案包含管理／重連憑證，勿放入公開靜態目錄。可用 `--data-dir 路徑` 指定獨立資料目錄。

預設提供 A～D 四個賽場，管理中心可新增、重新命名、停用或移除空閒賽場；預設上限 8，可用 `--max-arenas 1～16` 設定。降低上限前需先移除多餘空閒賽場。賽場數是管理容量，實際可同時流暢運算的場數取決於主機與場上機體數，本次已驗證兩場同時運作。未指定網卡而有多張可用網卡時，伺服器要求使用 `--address` 明確選擇。

大廳的「正式賽」有「本機伺服器正式賽・平板連線」入口。從專用 HTTPS 伺服器的大廳進入會帶入紅藍編成與 AI 難度；直接開啟檔案或使用原靜態伺服器時，該入口先顯示啟動說明。其他單機模式的開始按鈕與控制方式保留。

## 舊版區網模式：HTTPS、憑證與防火牆

1. 主機與平板須位於彼此可通訊的網路。Wi-Fi AP 的「用戶端隔離／訪客隔離」、VLAN 或學校防火牆可能阻止連線，即使名稱是同一個 Wi-Fi。可用網線連主機、Wi-Fi 連平板，只要路由可互通。
2. 建議在路由器保留主機 DHCP 位址。IP 改變後，先重新產生含新 IP 的憑證，再用新 IP 啟動；舊加入網址與舊 QR 不再適用。可以一次涵蓋多個已確認的位址：`python setup-certs.py --address 192.168.10.2 192.168.50.2`。
3. 憑證預設放在使用者家目錄的 `.webduino-lan/tls`，不放入專案。`--out` 可指定產生目錄，伺服器相應使用 `--cert-dir`。CA 有效期五年、伺服器憑證一年；再次執行會沿用原 CA，更新伺服器憑證。伺服器啟動時驗證憑證涵蓋所選 IP 且未過期。
4. **只把 `webduino-lan-ca.crt` 公開根憑證安裝到主機與平板的信任區**。`ca-key.pem` 與 `server-key.pem` 留在主機，伺服器不提供下載私鑰的路由。安裝前可核對產生工具印出的 CA SHA-256 指紋。
5. 主機 Windows 可在憑證管理員匯入「目前使用者／受信任的根憑證授權單位」，或執行下列明確指令。這份專案不會自動更動系統信任區：

```powershell
certutil -user -addstore Root "$env:USERPROFILE\.webduino-lan\tls\webduino-lan-ca.crt"
```

iPad：下載公開根憑證並安裝描述檔後，還需到「設定 → 一般 → 關於本機 → 憑證信任設定」啟用該根憑證的完整信任，然後重新開啟 Safari。手動安裝描述檔不會自動取得 SSL 信任。[Apple 官方說明](https://support.apple.com/en-us/102390)

Android：在裝置安全性／憑證設定中，將公開根憑證安裝為使用者 CA，依平板品牌的系統介面操作；受管理裝置可能需要管理員佈署。完成後在目標瀏覽器確認 HTTPS 無憑證錯誤。各品牌與瀏覽器對使用者 CA 的支援仍需現場實測，不能以按下「繼續前往」取代信任設定。

Gamepad API 需要安全來源及瀏覽器的裝置啟用規則。玩家頁面會檢查 `isSecureContext`、`navigator.getGamepads`、存取例外與搖桿回中狀態，並提供具體提示。網頁以 `wss://` 連線，沒有不安全 HTTP 遊戲或 `ws://` 降級。[Gamepad 規範](https://www.w3.org/TR/gamepad/)

玩家控制器採約 32ms 的獨立計時取樣，不依賴 3D 畫面的幀率。準備按鈕會等待控制器回中與實際視角同步，按下時同步重新讀取健康中立訊號，並在同一條 WSS 先送輸入、再送準備。校正、對話框、背景、失焦及離頁仍立即停止操作；頁面離開時清除取樣計時器，從瀏覽器快取返回時重新啟動。伺服器的 600ms 輸入逾時安全暫停規則維持原樣。

Windows 若出現防火牆詢問，允許 Node 在目前的私人網路接收連線。需要手動建立規則時，在管理員 PowerShell 執行：

```powershell
New-NetFirewallRule -DisplayName 'Webduino LAN HTTPS' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8443 -Profile Private -RemoteAddress LocalSubnet
New-NetFirewallRule -DisplayName 'Webduino LAN certificate setup' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8081 -Profile Private -RemoteAddress LocalSubnet
```

若學校政策使用其他網路設定檔，請由網管建立對應規則。無需開啟路由器對外轉發。一般現場應保留 `--setup-port`，讓新裝置先完成安全導入；只有所有裝置都已完成信任時，才省略此選項並直接使用 HTTPS。伺服器實際監聽全部本機介面，公布與 WSS Origin 僅接受啟動時選定的 LAN 位址。

### 首次掃碼與安全導入

啟用 `--setup-port 8081` 時，房間 QR 會指向 `http://LAN-IP:8081/?code=六位房碼`。主持人的複製加入網址與主選單「連線與賽事」設定，也優先使用這個公開導入入口；邀請視窗另保留已信任裝置的直接 HTTPS 連結。未啟用設定連接埠時，QR 維持直接 HTTPS，尚未信任的裝置應先完成憑證設定再開啟。

導入頁只提供 `GET /`、`GET /setup` 與公開 `GET /ca.crt`。頁面先向固定 HTTPS `/api/health` 發送 `no-cors`、不帶 Cookie 的連線探測。瀏覽器確認 TLS 成功後，才導向固定 `/play` 或經房間代碼驗證的 `/play?code=...`；未信任、憑證錯誤或主機離線時，保留在設定頁顯示安裝與重新檢查步驟。HTTP 不提供比賽、控制封包、帳號或管理金鑰，也不提供私鑰。此流程沒有略過憑證錯誤或自動安裝根憑證。

iPhone／iPad 需在安裝描述檔後啟用完整信任，Android 的安裝位置依廠牌而異；導入頁提供 [Apple 官方信任說明](https://support.apple.com/zh-tw/102390) 與 [Google 官方安裝說明](https://support.google.com/pixelphone/answer/2844832)。正式的已信任裝置自動進入、實體 QR 掃描及 Gamepad 相容性仍需現場驗收。這次開發驗證未更動作業系統或瀏覽器的信任設定。

2026-11-02 視角規則修正：依使用者說明，「統一視角」採各隊己方短邊的固定站位，取代先前第一／第三人稱跟隨設定。舊房間重新載入後轉為固定中間；轉播鏡頭的全場、固定機位及追蹤功能獨立保留。

## 主持人操作

服務入口與出口：

| 入口 | 用途與返回方式 |
| --- | --- |
| `/` 公開賽事大廳 | 顯示賽場、各房編成／人數／狀態／比分，可直接加入、觀看或輸入代碼；主持人連結進入管理中心 |
| `/admin` 服務管理中心 | 登入後管理所有房間、建立指定賽場的比賽、配置賽場、查看近期結果；登出只撤銷管理權限，不停止比賽 |
| `/host?code=XXXXXX` 房間主持人 | 每房獨立的單屏管理與轉播；左上返回管理中心，房間持續運作 |
| `/play?code=XXXXXX` 玩家 | 啟用導入埠時，掃碼先確認安全連線再進入；也可由已信任的大廳輸入代碼。「離開房間」釋放席位，進行中會自動暫停該房；一般網路斷線則保留席位等待原玩家 |
| `/watch?code=XXXXXX` 觀眾 | 該房現場轉播；左上返回公開大廳，離開觀眾頁不停止比賽 |

在管理中心建立房間時，設定房間名稱、空閒賽場及隊伍編成。等待／進行／暫停中的房間各占一個賽場；沒有空閒賽場時會明確拒絕建房。結束比賽會保留結果並釋放賽場，關閉房間則撤銷原代碼／QR 並保留歷史紀錄。各房最多六真人，其他房間的玩家與比賽不受本房操作影響。

主持人頁面採單屏配置，以「隊伍編成／玩家・比賽／統一視角／QR／加入」分頁切換管理項目，不需上下捲動。窄視窗另可在「賽事轉播／主持人管理」切換；寬視窗同時顯示轉播與管理區。有真人席位時建房會自動彈出邀請，關閉視窗後，QR、玩家網址、房間代碼與等待人數仍保留在「QR／加入」分頁，可隨時複製或放大。

開賽前的全場預覽採較高的俯視角，套用既有場館燈光、草皮與柔和陰影。待賽觀眾畫面會淡化頂框與護網以顯示球門及起飛區，開賽後恢復正常材質；玩家畫面使用正常場地顯示。原全場、固定機位與指定無人機追蹤操作均保留。

主持人與觀眾的轉播畫面依實際可用寬高取景，固定機位會自動保留完整球場；玩家仍遵守統一 16:9 視野。等待開賽與局間休息以轉播狀態列顯示。重新進入房間會先等待最新 3D 畫面完成同步，才移除載入提示；局間休息時無人機返回起飛區屬正常賽制。

管理中心採全視窗工作台，桌面依可用寬高分配導覽、賽事概況、即時轉播及房間列表；房間多時在列表內捲動，賽場與紀錄頁也各自使用可用高度。可搜尋房名／代碼／賽場並篩選狀態，正在預覽的房間會標示。窄螢幕改為上下排列，無水平溢位。

管理中心提供同場即時全景預覽，自動選擇進行中的房間，也可手動切換。點「即時觀賽」或「進入主持人房間」會回到該房持續運作的權威比賽，沒有另開展示賽。右側管理採紅藍隊緊湊席位卡片與本機 SVG 圖示。

尚未建房時，「QR／加入」會顯示實際區網玩家網址，以及「建立房間並顯示 QR」按鈕；不會產生無效的示意 QR 或代碼。關閉房間會清除舊資訊，新房會取得新的 QR 與代碼。

1. 開啟終端機印出的服務管理網址，按「建立房間」。設定房間名稱、賽場與紅藍兩隊，各隊合計 1～3 台；第一台前鋒，其餘防守，真人優先從前鋒開始配置。支援全真人、混合與全 AI。
2. 選擇 AI 難度與局間休息 2 或 3 分鐘，按「建立正式賽房間」。有真人席位時自動開啟邀請視窗，同時顯示 QR、手動加入網址、六位房間代碼及加入／等待人數。視窗可關閉、重新開啟與複製。
3. 開賽前可更新編成。仍然存在的真人席位與連線保留；轉成 AI 或被刪除的席位會釋放，相關玩家憑證失效。編成改變後場景重新同步，玩家需再準備。
4. 檢查每席的等待／已加入／搖桿連線／準備／斷線狀態。可移除玩家、釋放席位。鎖定新玩家不影響持原重連憑證的玩家恢復席位。
5. 統一選擇己方短邊的固定中間／左邊／右邊站位，設定垂直 FOV、網外後退距離與眼睛高度。紅隊站紅色短邊（-Z），藍隊站藍色短邊（+Z）；左右以各隊面向場內為準，因此兩隊鏡像。同隊所有角色共用機位，鏡頭固定看向場內，不隨機體位移或轉向。所有平板用相同 16:9 視野，其他螢幕比例留黑邊；不給寬螢幕額外視野。
6. 所有真人都須搖桿正常、3D 場景與視角版本同步、回中且準備完成，才能開始。全 AI 只需引擎就緒。保留原正式賽倒數、哨音與哨音後起飛規則。
7. 「觀眾轉播」在獨立頁面顯示同場賽況，可全螢幕，沒有管理面板。主持人切換全場、固定中／左／右或追蹤指定機體；這些操作不會變更玩家鏡頭。
8. 進行中不能變更玩家鏡頭。先暫停，再套用；每個玩家實際完成該版視角繪圖並重新準備後，主持人才能按「恢復」。
9. 真人中斷不會自動改成 AI。暫停後可用「替換 AI」明確接手同一台無人機。已開始比賽不允許任意增減場上機體；需要重新編成時關房再建新房。
10. 「結束本場」停止比賽、保留目前比分／局數並釋放賽場，可繼續查看結果。「關閉房間」會使代碼／QR 失效、釋放席位並移到近期紀錄；可返回管理中心建立其他房間。關閉未開賽房也會釋放賽場。

## 玩家操作

1. 在平板作業系統中配對藍牙搖桿。網頁不使用 Web Bluetooth 配對；由 Gamepad API 讀取已被作業系統辨識的控制器。
2. 掃描房間 QR 直接進入對應房間，或開啟主機提供的 `/play` 網址輸入代碼。代碼不分大小寫，排除 I、O、0、1；代碼本身不是網路位址。
3. 輸入暱稱、選擇尚未占用的真人席位，確認例如「紅隊 1 號・前鋒」。AI 與已占用席位不可選。伺服器確認占用，兩台同時搶同席只有一台能取得。
4. 按搖桿任一按鍵啟用瀏覽器偵測。確認名稱、四個方向與按鈕。沿用共用 USB 輸入的自動配置、RC／標準手把／USB Joystick 預設、死區與校正函式。
5. 有需要時選控制器、修改四軸索引及反向。雙桿回中後記錄中立點；全行程校正時走完所有正負方向，回中再完成。每個控制器設定保存在該平板瀏覽器。
6. 左桿升降／偏航，右桿前後／平移，方向以機頭為準；固定使用原定高飛控。換檔預設 B0，可在測試區改成實際按鈕索引，沿用 33.3／66.6／100% 檔位。鏡頭按鍵無法切換主機規則。
7. 放開全部按鈕，雙桿回中至少半秒，按「準備完成」。等待主持人開賽。聽到哨音後依既有啟槳／上推方式起飛，亦支援上推、回中、再上推。
8. 飛行時顯示己方短邊的固定即時視角（仍只控制自己的席位）、隊伍／席位／角色、比分時間局數、主機視角、搖桿與網路狀態。建議橫向持平板；設定可收合。
9. 斷線、背景化、失去焦點、控制器中斷或輸入逾時會清除操作並暫停比賽。請回到原分頁，重新配對／偵測、放開按鈕、回中並重新準備，等待主持人明確恢復。不要改開新的無痕工作階段；原席位重連憑證保存在原瀏覽器分頁工作階段。

同一瀏覽器的裝置識別避免多個分頁重複占用不同席位。主持人移除後原憑證永久失效。若清除網站資料或關閉原分頁而失去重連憑證，請主持人釋放原席位，再重新加入。

## 同步與故障處理

- Node 的 `EnginePool` 管理共用 headless Chromium，每個房間各有獨立 `EngineRunner`、browser context 與權威頁面。該房唯一執行物理、AI、得分、時間與局數的元件，是它載入的既有 `radio/drone_soccer_competition_add_ai_realgame.html` 引擎。主持人及平板僅使用同一場景的純繪圖模式。單場頁面故障只暫停該房；共用 Chromium 或主機停止則會影響所有場。
- 約 30 Hz 輸入、20 Hz 狀態快照；玩家與觀眾使用約 80 ms 緩衝的線性位置／四元數插值。平板不做位置預測、碰撞或計分。
- 快照包含無人機與可擺動球門的姿態。碰撞後的球門、計分帶及懸索同步顯示；球門位置、旋轉、速度及角速度也保存在權威復原檢查點。
- 每筆輸入綁定伺服器席位、連線 session、遞增序號、操作 epoch，以及 400 ms 有效的伺服器票據。暫停／恢復、移除與重連使舊操作失效；600 ms 沒有有效玩家輸入自動暫停。
- 權威頁面 350 ms 未收到伺服器控制會先停止模擬；Node 監測快照中斷並標示暫停。主持人頁面重新整理不重開引擎、不重設進度。
- 專用引擎程序中斷後，可由主持人按「從最後同步狀態復原引擎」。伺服器先關閉舊運算環境，再載入最新記憶體檢查點。比分、時間、局數、機體位置／速度及 AI 階段保留；所有玩家必須再次同步、回中及準備，最後由主持人恢復。
- **引擎故障復原的限制**：記憶體檢查點間隔約 50 ms，磁碟保存約 2 秒；碰撞接觸／網體變形、旋轉物理暫存及尚未完成的穿環過程會重置，機體接觸後的旋轉可能略有不同。若影響競賽判定，主持人應結束該房間並重賽。服務資料格式損壞時會停止啟動並保留原檔，請先備份再從 `.bak` 修復。
- 視角權限與參數由伺服器管理，玩家通訊無法呼叫主持人操作，繪圖每幀按規則套用；此版本沒有防篡改客戶端或影音串流，不能防止刻意修改瀏覽器程式的作弊者。適用由現場管理的平板；如需對不受信任裝置提供強制視野保密，需另外採用伺服器繪圖串流。

## 測試

```powershell
cd apps/drone-soccer/lan
npm test
npm run test:network
npm run test:browser
npm run test:scene
npm run test:controller
npm run test:layout
npm run test:invite
npm run test:service
npm run test:persistence
npm run test:service-ui
npm run test:admin-layout
```

整合測試使用實際網卡 IPv4、9443～9453 的測試連接埠與預設憑證目錄；主機需要已安裝 Chrome。測試使用記憶體資料或獨立暫存資料目錄，不改動正式服務資料。可用環境變數 `LAN_TEST_ADDRESS` 選測試網卡。WSS／Node TLS 使用產生的 CA 驗證；桌面瀏覽器自動化使用 `ignoreHTTPSErrors`，因此不驗證平板的系統憑證安裝。瀏覽器的兩支搖桿是合成 Gamepad API 訊號。

2026-11-03 新增設定與安全導入回歸，必須指定獨立測試憑證目錄，不讀寫正式服務資料或系統信任區：

```powershell
$env:LAN_TEST_CERT_DIR='C:\path\to\isolated-test-tls'
$env:PLAYWRIGHT_BROWSERS_PATH=(Resolve-Path ..\runtime\ms-playwright).Path
& ..\runtime\node\node.exe test/panel-settings.cjs
& ..\runtime\node\node.exe test/certificate-setup.cjs
```

設定測試使用 9468 埠、完整 bundled Chromium、真實 HTTPS／WSS 房間與合成 Gamepad，將玩家繪圖限制到 4fps，驗證獨立控制計時、準備、校正儲存／取消、視角鎖定與自訂確認操作。安全導入測試使用 9470／9471 埠，以 Node `https` 搭配指定 CA 且 `rejectUnauthorized:true` 驗證伺服器憑證，再以全新 `ignoreHTTPSErrors:false` 瀏覽器確認未信任探測被阻擋且留在導入頁。成功跳轉分支使用受控 `fetch` 回應，主選單公開入口檢查使用忽略測試 CA 的 UI context，這兩項不代表正式已信任裝置實測。相關報告與桌面／320px／橫向截圖在 `artifacts/all-interfaces-20261103/lan/`。

正式設定驗證明確指定 `executablePath: chromium.executablePath()`，使用遊戲 runtime 的完整 Chromium；權威引擎維持原本 bundled runner。最終六機流程通過：2 秒內玩家繪圖 8 幀、輸入年齡最高 47ms、開賽階段已接受輸入的最大間隔 48ms；準備、實際開賽、背景安全暫停、重新準備／恢復、主持人暫停、視角變更清除準備、AI 接手及終場紀錄均走真實 API，沒有 JavaScript 錯誤。`settings/report.json` 為正式證據；`settings/system-chrome-diagnostic.json` 只保留系統 Chrome 對照，不列為交付瀏覽器驗證。預設 Playwright `headless_shell` 的低速渲染診斷亦不可代替完整 runtime 瀏覽器結論。

原正式賽成果在專案根目錄 `artifacts/lan-official-20261101/`；多賽場、服務進出與磁碟復原報告在 `artifacts/lan-service-20261102/`。實體平板、藍牙搖桿、實際 Wi-Fi 延遲與長時間比賽需依驗證文件現場完成。
