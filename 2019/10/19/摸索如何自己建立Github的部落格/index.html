建立 GitHub 個人部落格：Hexo 與 NexT 設定筆記

2019.10.19黃永成約 15 分鐘閱讀更新於 2026.09.30

2019 年，我從 GitHub Pages、Hexo 與 NexT 開始建立自己的部落格。這篇保存當時的環境、主題設定、文章編輯與部署流程，也留下調整版面的實作筆記。

本篇重點
  • 建立 GitHub 專案與 Hexo 本機環境
  • 調整 NexT 導覽、版面與閱讀功能

操作說明

Github repo 設定 & Hexo 搭建

個人網站與專案網站的差別在儲存庫名稱及網址路徑；下方 master、gh-pages 是原紀錄的發布分支選擇，不是只能使用這兩個分支。實際發布來源依 GitHub Pages 設定確認。

至 https://github.com/ 申請一個帳號。
登入之後，尋找一下建立儲存庫的按鈕(頁面右上角的加號)，選擇 New repository (建立儲存庫)

先決定使用個人網站或專案網站，兩者的網址與路徑設定不同：

  1. 以<個人帳號>.github.io為專案名稱，使用 master branch 建構，
    這樣生成的網址會是 https://<個人帳號>.github.io。

  2. 以自訂專案名稱 <倉庫名稱> ，使用 gh-pages branch 建構，
    這樣生成的網址會是 https://<個人帳號>.github.io/<倉庫名稱>。

我個人做的是想把網址簡單化，因此想保留 https://<個人帳號>.github.io 作為首頁網址，

步驟 1：新增一個 Github New repository

在個人的 Github 頁面上新增一個 New repository 。

步驟 2 : 安裝 Node.js 套件管理工具

  1. 安裝Git，至Git官網下載，安裝即可。

  2. 我們可以從Node.js 官網下載安裝，安裝完後至終端機輸入

    輸出版本後，便表示安裝已完成。若終端機找不到新安裝的指令，先重新開啟終端機，確認 PATH 與版本。當時我曾透過重新開機排除問題，但不是每次安裝都必須重開機。

步驟 3 : 安裝 Hexo

先打開cmd終端機，cd 到你想要安裝目錄，我個人是選擇在隨身硬碟的F:槽裡安裝，方便之後換電腦維護編輯部落格。若要換電腦維護編輯部落格，也是要將Hexo和Git、Node.js安裝完成，也就是步驟 2和步驟 3的步驟要做完。開始安裝Hexo

hexo server 和 hexo s 是相同意思的，
輸入hexo s後，在網址列輸入http://localhost:4000，若網頁正常顯示，表示安裝成功。

Hexo 的 hexo d 部署登入問題與解決方式

下方保留 classic token 的操作路徑。新設定可依 GitHub 文件評估 fine-grained token、期限與指定儲存庫；Token 不應寫進文章、設定檔或公開儲存庫。

以 HTTPS 部署且尚未設定認證工具時，Git 可能提示輸入帳號與憑證。認證方式取決於 Git 遠端網址與本機設定，不是每次 hexo d 都會詢問。
GitHub 的 HTTPS Git 操作不支援以帳號密碼認證，可使用 Personal Access Token（PAT）或支援的認證工具；SSH 遠端則使用另一種設定。

登入流程

  1. 終端機會要求輸入：

    → 這裡請輸入 GitHub 註冊的信箱（或 GitHub 帳號名稱）。

  2. 接著會要求:

    → 這裡請輸入 Personal Access Token (PAT)，而不是 GitHub 的密碼。

Personal Access Token 產生方式
1. 登入 GitHub。
2. 點選右上角大頭照 → Settings (設定)。
3. 左側選單找到 Developer settings (開發者人員設定)。
4. 點選 Personal access tokens → Tokens (classic)。
5. 按下 Generate new token (產生新令牌)，依需求勾選權限（依目標儲存庫與操作給予必要權限，勿把廣泛的 repo 權限視為所有情境都需要）。
6. 產生後會得到一串字元，請將它複製保存（之後在 hexo d 輸入密碼時，就是貼上這個 Token）。

文章類型：

  1. post：最常碰到的一般文章。
    新增的檔案會放在\source\_posts資料夾內建立[檔名].md的檔案。-
  2. page：不會出現在首頁中。
    基本上拿來撰寫about或tags之類的頁面。
    這類型會在\source\下建立檔名資料夾，並在檔名資料夾下新增index.md檔案。
  3. draft：草稿。
    未完成的文章可先放在草稿區。一般生成不會包含草稿，但仍需留意 render_drafts 或生成時的草稿選項。
    草稿會存放在\source\_drafts底下，檔名為檔名.md。
    編輯完後，可以透過指令hexo publish draft 檔名轉成正式文章；之後仍需生成與部署，公開網站才會更新。
    再來選擇一款合適自己的md編輯器，和使用一些常用md語法就能完成一篇文章了。

設定首頁文章【繼續閱讀】功能

【繼續閱讀】
在部落格首頁時，會將每篇文章以全文方式顯示，但有些文章太長了，導致要拖拉很久才能找到下一篇。
