ChatGPT 實務應用：能力、限制與 API 入門

2023.09.06黃永成約 5 分鐘閱讀更新於 2026.09.30

我在使用 ChatGPT 與串接服務的過程中，最常遇到的問題不是如何提問，而是如何判斷回答是否可靠。這篇整理文字生成的用途、服務整合的限制，以及 API 使用前需要了解的基本觀念。

本篇重點
  • 分清楚模型生成的回答與已查證的資訊
  • 從資料時效、對話成本與回答品質評估整合方式
  • 了解 API 金鑰與舊版 Python 範例的用途

原始實作記錄於 2023 年；以下操作畫面與程式範例保留當時版本。

以下程式碼保留 2023 年的 SDK 寫法；請勿直接視為目前版本的使用方式。官方 API 價格 · 服務整合與限制

從文字工具開始認識 ChatGPT

什麼是 AI 聊天機器人？

AI 聊天機器人以語言模型等技術處理使用者的輸入，並生成回應。對話內容可作為回答的上下文，但不代表模型在每次聊天後都會自行更新訓練結果。

除了對話，這類工具也能協助翻譯、改寫文章和產生程式碼。對我而言，它的價值在於先整理出一份可討論的草稿，再由使用者補足情境、查證內容並完成修改。

ChatGPT 為什麼討論度這麼高？

我過去接觸的語音助理，多半用來執行查詢或控制裝置。接觸 ChatGPT 後，我更常把問題、資料或草稿交給它，透過文字對話逐步調整內容。這裡記錄的是自己的使用方式，而不是對各產品能力的完整比較。

例如，可以先請它整理文章重點，再要求改寫不清楚的段落；開發程式時，也能用它討論函式設計或閱讀錯誤訊息。不過，生成的內容仍是待確認的草稿，程式碼也需要在自己的環境中測試。

使用時，我會先交代目的、讀者與限制，讓回答更貼近需求；若結果不合適，再指出需要修改的地方，而不是一次接受整份輸出。

ChatGPT 是誰發明的？

ChatGPT 是 OpenAI 開發的對話服務。本文記錄的是 2023 年的使用經驗，當時討論的模型包含 GPT-3.5 與 GPT-4；今天閱讀時，不宜把這些名稱與方案限制直接套用到目前的服務。

ChatGPT 由 OpenAI 開發。實作時，我更關心它能否理解問題、整理資料與協助撰寫程式；企業合作、使用者規模或特定能力測試，不能直接當作服務可靠性的證明。

因此，評估工具時，我會回到實際任務：它是否減少整理資料的時間？輸出能否查證？遇到錯誤時，是否有其他處理方式？

ChatGPT 能做到什麼事？

在文字工作上，可以用它協助整理重點、修正文句、翻譯或擬定回覆；在程式開發上，則可用來討論做法、產生範例或解釋程式。輸出是否可用，仍取決於需求是否清楚，以及後續的人工檢查。

資料時效取決於使用的模型與工具。本文的早期整合經驗沒有接上即時資料來源，因此回答可能落後於現況；需要最新資訊時，應查閱來源並核對時間。

ChatGPT 如何註冊？

若要開始使用，可從官方網頁確認帳號建立與登入方式。
使用手機時，可從官方發布的 Android 或 iOS 應用程式進入服務。
下載連結：Android / iOS / 網頁官網

帳號建立方式與驗證要求可能調整，請依官方網站目前顯示的流程操作。

先分清楚對話服務與 API 用量

本文不固定列出訂閱價格；請在選購前查閱官方當期方案。

  • 使用 API key時，請確認 API 平台的計費與用量設定。金鑰是存取憑證，實際費用與 API 呼叫用量有關。

整合進服務前，需要釐清的三件事

  1. 語言模型會根據輸入與上下文生成回應。若沒有接上外部搜尋或資料來源，就不應假定它掌握即時資訊；模型參數量也不能直接代表回答的正確性。

    • 我曾透過 API 串接 LINE Bot，詢問當時正在上映的電影，卻得到「黑寡婦」「永恆族」等較早的片名。這個例子提醒我：沒有接上適當資料來源的回答，不適合直接當作即時查詢結果。

  2. 對話長度與使用成本
    在這份早期串接範例中，程式會把需要的歷史對話放進下一輪請求，讓模型理解前後文。評估成本時，除了回答長度，也要考慮帶入多少歷史內容、呼叫頻率與所使用的模型，不能只看單次回覆。

  3. 把模型整合進服務前，應先定義回答範圍、測試情境與人工處理方式。模型仍可能產生不準確或不合適的內容，需要持續評估使用結果。

    • 例如，使用者詢問服務的優缺點或與其他產品的差異時，應先界定可回答的資料範圍；資料不足的問題，則交由人工補充，而不是讓模型自行推測。

建立 API 金鑰與確認環境

使用 API 前，請先確認帳號的用量、付款與費用設定。優惠額度與資格可能調整，不應把舊版優惠當作固定條件。https://platform.openai.com/account/api-keys

  • api-key Python套件安裝

  • 原始畫面中的「Create new secret key」用來建立 API 金鑰。介面位置可能調整，操作時請以 API 平台實際顯示的項目為準。

    建立金鑰後，依畫面提示保存 Secret Key；原始介面只在建立時顯示完整內容。
    不要把金鑰放進公開文章、截圖或程式碼儲存庫。

  • 若無法取得原有金鑰，應在平台建立替代金鑰，並確認舊金鑰是否需要撤銷。應用程式可從伺服器的環境變數或金鑰管理服務讀取憑證，避免在程式碼中寫入真實金鑰。
